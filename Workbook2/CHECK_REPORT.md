## Что нельзя обещать без правил проверяющей программы

1. **С6: история коммитов.** Старые `Ws1` и `Revork` остаются в истории.
   Исправить их названия без переписывания истории невозможно. Это требует
   отдельного разрешения; история не изменена.
2. **Г2: PDF.** По запросу пользователя `README.pdf` убран из текущего
   дерева Git и добавлен в `.gitignore`. Локальная копия сохранена.
   Файл остается в старых коммитах: история не переписана.
3. **Г4 и Р6: результаты визуализации.** SVG, D2 и протоколы сравнения нужны
   для демонстрации этапа 5. Внутри SVG могут быть длинные машинные строки.
   Если программа проверяет все файлы как исходный код, возможны замечания.
4. **И1: unittest.** `setUp` — имя обратного вызова `unittest.TestCase`.
   Переопределения такого интерфейса не нарушают соглашения Python.
   Исключение явно отражено в конфигурации Ruff. Нельзя просто переименовать
   метод, иначе подготовка тестов перестанет выполняться.
5. **Область проверки.** Эта правка исправляет этапы 4–5, их общие проверки,
   инструменты и структуру корня. Работу 1 и монолитные снимки этапов 1–3
   не следует считать прошедшими полный аудит по данному перечню.

Это воспроизводимая проверка указанных порогов, а не гарантия результата
неизвестной программы преподавателя. Для полного совпадения нужен ее
фактический вывод с путями и номерами строк.
