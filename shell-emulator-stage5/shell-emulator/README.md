# Эмулятор оболочки UNIX

Эмулятор командной строки UNIX-подобной ОС на Python с графическим
интерфейсом (`tkinter`). Текущее состояние: **этап 5 — дополнительные
команды** (включает этапы 1–4: REPL, конфигурацию, VFS и основные
команды).

## Возможности

| Этап | Что реализовано |
|------|-----------------|
| 1. REPL | GUI, заголовок `Эмулятор - [user@host]` из данных реальной ОС, раскрытие `$HOME`, сообщения об ошибках, команда `exit` |
| 2. Конфигурация | Параметры `--vfs`, `--prompt`, `--script`, отладочный вывод параметров, стартовый скрипт с показом ввода и вывода |
| 3. VFS | Загрузка VFS из ZIP-архива в память, base64 для двоичных данных, ошибки загрузки, VFS по умолчанию, служебная команда `vfs-info` |
| 4. Команды | Настоящие `ls` и `cd` (текущая папка, `.`/`..`, абсолютные и относительные пути), `history`, `who`, `head` |
| 5. Изменение VFS | `touch` и `rm`: создание и удаление файлов и папок, только в памяти |

## Структура репозитория

```
.
├── src/
│   ├── emulator.py     # точка входа
│   ├── config.py       # параметры командной строки, загрузка VFS
│   ├── shell.py        # парсер, состояние оболочки (cwd, history)
│   ├── commands.py     # команды: ls, cd, history, who, head, touch, rm
│   ├── result.py       # Result и CommandError
│   ├── vfs.py          # виртуальная файловая система, пути
│   └── gui.py          # графический интерфейс
├── tests/
│   ├── test_emulator.py     # тесты парсера, оболочки и VFS
│   ├── test_commands.py     # тесты команд этапов 4 и 5
│   ├── helpers.py           # вспомогательные функции тестов
│   ├── make_vfs.py          # генератор тестовых ZIP-архивов
│   ├── start_all.txt        # стартовый скрипт этапа 3
│   ├── start_stage4.txt     # стартовый скрипт этапа 4
│   ├── start_stage5.txt     # стартовый скрипт этапа 5
│   └── test_stage3/4/5.sh/.bat  # сценарии (Linux / Windows)
├── run.sh                   # запуск (Linux/macOS)
├── run.bat                  # запуск (Windows)
├── .gitignore
└── README.md
```

Тестовые ZIP-архивы в репозитории не хранятся: их создаёт
`tests/make_vfs.py` (папка `tests/vfs_samples/` в `.gitignore`).

## Требования

- Python 3.8+, только стандартная библиотека
- Для GUI нужен `tkinter` (Linux: `sudo apt install python3-tk`)

## Запуск

```
./run.sh [--vfs ZIP] [--prompt "СТРОКА"] [--script ФАЙЛ] [--headless]
run.bat  [--vfs ZIP] [--prompt "СТРОКА"] [--script ФАЙЛ] [--headless]
```

| Параметр | Описание |
|----------|----------|
| `--vfs` | Путь к ZIP-архиву с VFS. Без него создаётся VFS по умолчанию в памяти |
| `--prompt` | Своё приглашение к вводу. Без него показывается `[user@host /путь]$ ` с текущей папкой |
| `--script` | Путь к стартовому скрипту |
| `--headless` | Консольный режим без GUI (для автотестов) |

При запуске все параметры выводятся в отладочном виде:

```
[debug] параметры запуска:
[debug]   vfs    = tests/vfs_samples/deep.zip
[debug]   prompt = deep# 
[debug]   script = tests/start_stage5.txt
```

## Команды

| Команда | Описание |
|---------|----------|
| `ls [-l] [-a] [путь...]` | Содержимое папки или сведения о файле. `-l` — тип (`d`/`-`) и размер, `-a` — скрытые (`.имя`). Ключи объединяются: `-la`. Для нескольких путей выводятся заголовки `путь:` |
| `cd [путь]` | Переход в папку VFS. Поддерживаются `.`, `..`, абсолютные и относительные пути. Без аргумента — в `/home/user` (если её нет — в корень) |
| `history [N]` | Нумерованный список введённых команд (включая ошибочные); с аргументом — последние N |
| `who [-q]` | Пользователь реальной ОС, терминал, время входа и хост; `-q` — только имена и их число |
| `head [-n N] файл...` | Первые N строк (по умолчанию 10); `-n 3` и `-n3` равнозначны. Для нескольких файлов — заголовки `==> файл <==`. Двоичные файлы — в base64 |
| `touch файл...` | Создаёт пустые файлы. Существующие файлы и папки не меняются. Родительская папка должна существовать |
| `rm [-r] [-f] путь...` | Удаляет файлы. Папки удаляются только с `-r` (вместе с содержимым). `-f` подавляет ошибку для несуществующих путей. Ключи объединяются: `-rf` |
| `exit` | Завершает работу |
| `vfs-info` | Служебная: источник VFS и дерево файлов (удобно смотреть результат `touch` и `rm`) |

Парсер раскрывает переменные окружения реальной ОС (`$HOME`, `${HOME}`)
и понимает кавычки.

### Изменение VFS только в памяти

`touch` и `rm` меняют дерево в памяти. Исходный ZIP-архив не
модифицируется и не распаковывается: после выхода из эмулятора файл
остаётся прежним, а при следующем запуске VFS загружается заново. Это
проверяется модульным тестом и сценарием `tests/test_stage5.sh`/`.bat`
(сравнение архива до и после).

`rm` не позволяет удалить текущую папку, любую из её родительских папок
(в том числе `.`, `..` и `/`): так оболочка никогда не остаётся в
несуществующей папке.

### Ошибки выполнения команд

| Ситуация | Сообщение |
|----------|-----------|
| Неизвестная команда | `foo: команда не найдена` |
| Путь не найден | `ls: невозможно получить доступ к '/nope': Нет такого файла или каталога` |
| `cd` в файл | `cd: /readme.txt: Не является каталогом` |
| `head` для каталога | `head: ошибка чтения '/home': Это каталог` |
| `touch` в несуществующую папку | `touch: невозможно выполнить touch для '/no/x': Нет такого файла или каталога` |
| `rm` для папки без `-r` | `rm: невозможно удалить '/etc': Это каталог` |
| `rm` текущей папки или родителя | `rm: невозможно удалить '/': это текущая папка или её родитель` |
| Неверный ключ | `ls: неверный ключ -- 'z'` |
| Неверные аргументы | `cd: слишком много аргументов`, `head: не указан файл`, `touch: пропущен операнд-файл`, `rm: пропущен операнд`, `history: abc: требуется числовой аргумент`, `who: лишний операнд 'now'` |
| Незакрытая кавычка | `эмулятор: ошибка разбора: ...` |

Если команда получила несколько путей, ошибка по одному из них не
мешает обработать остальные.

## Виртуальная файловая система

- Источник — ZIP-архив. Он читается через `zipfile` в память,
  **на диск ничего не распаковывается**.
- Двоичные данные хранятся как `bytes` и выводятся как `base64:...`.
- Пути с `..` внутри архива отклоняются.
- Без `--vfs` создаётся VFS по умолчанию (`/home/user`, `/tmp`).
- Текущая папка (`cwd`) и история команд хранятся в оболочке и живут
  только в памяти.

Ошибки загрузки VFS:

| Ситуация | Сообщение |
|----------|-----------|
| Файл не найден | `[vfs] ошибка загрузки: файл VFS не найден: ...` |
| Не ZIP-архив | `[vfs] ошибка загрузки: неверный формат VFS (не ZIP-архив): ...` |

## Стартовый скрипт

Команды выполняются построчно, на экране видны и ввод, и вывод.
Ошибочная строка пропускается с сообщением
`[скрипт] ошибка в строке N, строка пропущена`. Строки с `#` —
комментарии. Команда `exit` останавливает скрипт.

## Тестирование

```
sh tests/test_stage5.sh        # Linux / macOS
tests\test_stage5.bat          # Windows
```

Сценарий создаёт тестовые архивы (`minimal`, `several`, `deep` с
вложенностью 4 уровня, `broken`), запускает модульные тесты и
`tests/start_stage5.txt` на разных VFS, а в конце проверяет, что архив
не изменился. `start_stage5.txt` покрывает обе команды этапа, все их
режимы и все виды ошибок. Аналогичные сценарии для предыдущих этапов —
`tests/test_stage3.*` и `tests/test_stage4.*`.

Только модульные тесты:

```
PYTHONPATH=src python3 -m unittest discover -s tests
```

## Оформление коммитов

Используется Conventional Commits, например:

```
feat(repl): добавить GUI и парсер переменных окружения
feat(config): добавить параметры и стартовый скрипт
feat(vfs): загрузка VFS из ZIP-архива в памяти
feat(commands): добавить ls, cd, history, who, head
feat(commands): добавить touch и rm
```
